## Decisions the spec did not cover

1. **`anchorOffset` clamps at 0.** The criterion asks for `top - navH` "and 0 for `#top`" from a two-argument function, which can't see the hash. `Math.max(0, top - navH)` satisfies both literally — `#top` reports a document top of 0 — and is the correct behavior anyway for any anchor sitting under the nav. The `#top` branch itself stays in the DOM handler, where it belongs.
2. **A dead link keeps native behavior.** For a missing section I `return` *before* `preventDefault()` rather than swallowing the click, so the anchor stays a plain anchor. The browser no-ops on a fragment it can't resolve.
3. **The driver takes its start time from the first rAF timestamp**, not `performance.now()`. One less global to stub, and the start is the first painted frame rather than the scheduling moment.
4. **Half-filled circle via gradient, not the mock's trick.** The reference fakes the empty half with an inset shadow in the page background color; over the glass nav that would be visibly wrong, and the spec says *transparent*. Shipped `linear-gradient(to right, currentColor 50%, transparent 50%)` plus a 1px `currentColor` inset ring, `rotate(-30deg)`.
5. **The language label is derived, not written** — `${lang.toUpperCase()} / ${otherLang}` — so `ES / en` involves no hardcoded copy at all.
6. **`--nav-h` lives in `app.css` `@layer base :root`**, not in Nav's scoped style: the script reads it off `documentElement`, and Astro's scoping would not let a component `:root` rule match `&lt;html&gt;`.
7. **`&lt;a&gt;` inside `&lt;li&gt;` for the section links**, and `hreflang`/`rel` kept on the language anchor but the `lang` attribute dropped — it would have mislabeled the whole "ES / en" pair.
8. **No dependencies added.** The runtime verification uses a hand-rolled stub in the scratchpad rather than pulling in jsdom or happy-dom.

Focus rings, a11y audit, and the sections themselves stay out, per the spec.</result>
