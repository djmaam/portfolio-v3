**No-JS toggle** — served the real build with `bun run preview` and followed the anchors with curl (no JS anywhere in the loop):

```
GET /  → href="/en" rel="alternate" hreflang="en"
GET /en   status=200  &lt;html lang="en"  &lt;h1&gt;I think the product.
GET /en → href="/"   rel="alternate" hreflang="es"
GET /     status=200  &lt;html lang="es"  &lt;h1&gt;Pienso el producto.
```

**Redirect** — I extracted the *shipped* head script out of `dist/*.html` and executed it against a stubbed browser (scratchpad script, not committed), so this exercises the exact emitted code, not a re-implementation:

```
no navigation  ← / with no stored lang
replace(/en)   ← / with localStorage.lang='en'
no navigation  ← / with lang='en', already redirected this session
no navigation  ← / with lang='es' (agrees)
no navigation  ← / with junk lang='xx'
replace(/)     ← /en with lang='es'
no navigation  ← /en with lang='en' (toggle just wrote it)

sequence:
 1. open /     → replace("/en")
 2. now on /en → null
 3. back to /  → null   (no bounce)
```

`location.replace`, never `location.href`. The toggle's `localStorage.setItem` fires on click before navigation, so case 7 covers "explicit toggle wins". No real browser tooling was reachable from this environment, so the back-button step is verified at the script level (sessionStorage is per-tab and survives the replace; bfcache would skip the script entirely on back, which is strictly safer).

## Decisions the spec did not cover

1. **`tsc --noEmit` added to `bun run lint`.** The criterion asks the `Content`-is-derived check be a *compile-time* check, but nothing in the pipeline typechecked — `bun test` doesn't, and `ts.configs.recommended` isn't type-aware — so the assertion would have been decorative. I chained `tsc --noEmit` into the existing `lint` script (no new script key, so `tests/scaffold.test.ts`'s frozen script-set assertion still holds). That surfaced one pre-existing error, `baseUrl` deprecated in TS 6/removed in TS 7; I deleted `baseUrl` since `paths` resolves relative to the tsconfig without it. I confirmed the check bites: swapping `Content` for a hand-written `{ h1a: string }` makes `tsc` fail. Separate `chore` commit if you want to drop it.
2. **`stepVerbs` is a pipe-separated string, not an array.** "Same length in both languages" only makes sense as segment count, so the test compares `split('|').length` (5 = 5).
3. **`&lt;title&gt;` is `{t.eyebrow}`.** The old title was the hardcoded literal `Marcos Arrieta`, which the no-hardcoded-copy rule forbids and `content.json` has no name/title key for. `eyebrow` is identical in both languages and reads acceptably. Issue 03 owns the real meta layer.
4. **Toggle label is the language code** (`{otherLang}`, e.g. `en`), since there's no toggle-label key in content. Given no invented copy, accessibility rides on `hreflang` + `lang` + `rel="alternate"` on the anchor.
5. **Inline script gets its values via `define:vars`** rather than restating the path logic as a JS string. `siblingPath`/`langFromPath` can't be imported into an `is:inline` script, so the page computes `siblingHref` at build time and passes it in — one source of truth for the routing rules.
6. **Redirect guard is `stored === otherLang`, not `stored &amp;&amp; stored !== lang`.** The spec's snippet would redirect on a junk `localStorage.lang` value; comparing against the known other language ignores garbage.
7. **`siblingPath` preserves the sub-path** (`/en/x` ⇄ `/x`) instead of hard-returning `/` or `/en`. Same line count, and it avoids an unused `pathname` parameter that `@typescript-eslint/no-unused-vars` would reject.
8. **Head and markup are duplicated across both pages** rather than factored into a layout — spec §3 says issue 03 hoists it into `Base.astro`, and layouts are explicitly out of scope here.
