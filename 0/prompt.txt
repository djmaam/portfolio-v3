## Keyboard pass

**No browser automation is reachable in this environment** — no `mcp__claude-in-chrome__*` tools, no Playwright (out of scope per the spec anyway). I did not drive a real browser. What I did instead was dump the focusable sequence from both built routes and encode it as a test:

```

 9-10 hero CTAs     11-16 project cards            17 email        18-20 social pills
21 footer handle
```

Identical on `/` and `/en`, matches visual order, no positive `tabindex` anywhere (the only 5 are `-1`, all on preview iframes), so nothing overrides or traps the order. The nav-overlap risk is handled by `scroll-padding-top`. What I cannot certify without a browser: that the ring is *visually* unclipped everywhere (`overflow: hidden` on `.row`, `.preview`, `.edge` could crop a 2px offset ring on an element that sits flush against those edges). Worth one manual pass, or issue 17's Playwright run.

## Decisions the spec did not cover

1. **Weight 500, not larger type.** Eight rules painted small mono labels with the accent at weight 400. `DESIGN_SPEC` §6 offers "≥15px **or** weight 500" — I took the weight, since bumping sizes would be a restyle. 500 is inside the design's own 400–500 range for small mono labels. Note the design's rule is looser than WCAG, which puts large text at ≥18.66px bold / ≥24px; at 3.46:1 in light, these labels satisfy the design spec but not WCAG AA on their own. Raising the light accent would change the whole site's cyan, so I left it and flagged it here.
2. **`.handle` and `.status` take the weight at rest**, not in the hover/done state — changing weight on hover reflows the line. The test resolves the size/weight from the rule *or* from the rule for that element's own class, which is why this works.
3. **`Hero.astro`'s `.accent` restates `font-weight: 600`** (the h1's own). Redundant to the browser, but it is what makes the rule auditable without the markup beside it.
4. **About's lead became the `&lt;h2&gt;`.** It is what the other sections render as `&lt;h2 class="text-h2"&gt;`, and Tailwind's preflight resets heading size/weight to `inherit`, so nothing renders differently. The alternative — promoting the principle cards to `&lt;h2&gt;` — would have been semantically wrong.
5. **`aria-labelledby` over `aria-label`** for the six named sections: no copy duplicated, `content.json` stays the only source, and it avoids screen readers spelling out the all-caps `secAbout` values.
6. **`&lt;main&gt;` got `tabindex="-1"`** so the skip link moves focus and not just the viewport (Safari otherwise only scrolls).
7. **The skip link hides with `top: -100px`, not a transform** — nothing to animate for a `reduce` visitor, and it keeps the hover/transform sweep honest.
8. **No dependencies added.** Considered axe: it needs a DOM (jsdom + axe-core, two deps) and would *not* catch the two findings that mattered here — the token pair failure, because it never sees the dark theme's inverted card without rendering both themes, and the reduced-motion sweep, which it does not check at all. The CSS-parsing tests cover both and run in 0.9s with the build included.</result>
