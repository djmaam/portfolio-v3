## Decisions the spec did not cover

1. **`content.json` was not tree-shakeable.** Importing `consoleLog` into a client module pulled *all* of content.json into the console bundle — 5.9 kB gzipped against ~0.5 kB for every other script — because Vite stringifies large JSON into one `JSON.parse`. Fixed with `json: { stringify: false }` in `astro.config.mjs` plus named imports in `src/lib/content.ts` (own commit, `perf(build)`). Console script is now 831 B gz; all page copy still renders in both languages. This is the one change that touches shared code outside the block.
2. **Tick seeding.** The server renders `metricsAt(0)` (spec §8 is explicit), but the client seeds its counter at `MAX_LINES = 6` so the log continues at message 7 instead of repeating. The two counters therefore disagree for one frame — `shipped` steps 41 → 42 on the first tick. Documented in `consoleLog.ts`.
3. **Initial timestamps are backdated** by `INTERVAL_MS` each, so the six lines read as a log that has been running rather than six events in the same second. Spec only said "JavaScript fills the times".
4. **The cursor resets when the subscriber set empties**, so a fresh start always picks up right after the six lines in the markup. This is also what makes the cycle tests order-independent.
5. **`--color-shadow-console` is a new token** in `app.css`. The shadow is black in both themes, so it cannot be mixed from an existing token, and the no-literal-colors rule leaves app.css as the only home.
6. **`data-console` is a CSS-only hook.** The console's resting-state override lives in `app.css` next to the `[data-boot]` rule it overrides, rather than in the component, so cascade order between the global sheet and a scoped style is never load-bearing.
7. **Skipped from the mock, not in the spec:** the prompt row (`hh:mm:ss ▸` + blinking caret) and the gradient halo border with its inset shadow. Spec §1 lists three parts and a 1 px `--color-line` border; adding the prompt would also have meant a seventh time cell for no stated reason.
