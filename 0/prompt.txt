#### Important

**`src/components/CubeMark.astro:12` — the build-time SVG and the canvas's first frame are ~42° apart, so the mark visibly snaps on every page load. The comment two lines above claims the opposite.**

```
const polys = markPolygons(size, 1, 0, Math.PI / 4)
```

The SVG is baked at `spinY = π/4 ≈ 0.785 rad`. The canvas paints with `markSpin(now)` (`markDraw.ts:55`), where `now` is the rAF timestamp — time since the time origin, small at mount. At a 200–800ms mount, `markSpin(now)` is 0.056–0.224 rad. The cluster's world rotation therefore differs by 0.56–0.73 rad at handover. I measured the projected result at box=20: a max point displacement of ~14–16px inside a 20px box. `idleWobble` adds a second, smaller mismatch (`t = 0` in the SVG vs `t = now` on the canvas).

Why it matters beyond the pixels: the entire build-time-SVG design exists to avoid this. `CubeMark.astro:10-11` says "This is the exact frame the canvas takes over from, which is why there is no jump when it mounts: same module, same numbers", and spec 30:42-44 justifies the seeded LCG because otherwise "the mark visibly jumps when the canvas mounts". The arrangement is stable; the *pose* is not. The comment is load-bearing documentation that is false, and a future reader will trust it.

No gate catches it: `e2e/nav.spec.ts:128` only asserts that two frames 1200ms apart differ, which a jump satisfies as happily as smooth motion.

Fix, matching the convention `NodeNetwork` already uses (`network.ts:271`, `this.born`): give `Mounted` a `born` field set at mount, paint with `t = now - born` (rebasing `hoverAt` to the same origin — `mark.hoverAt = performance.now() - born` at `markDraw.ts:127`), and bake the SVG at `markPolygons(size, 1, 0, markSpin(0))`, i.e. `spinY = 0`. The first canvas frame then reproduces the SVG exactly, which is what both the comment and the spec already promise.

A cheaper partial fix — bake the SVG at `spinY = 0` and leave the clock alone — cuts the jump from ~42° to under 10° but does not eliminate it, and leaves the comment still overstating.
