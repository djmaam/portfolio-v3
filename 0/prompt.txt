## How the icons were verified

- In `dist/_astro/*.css` each pill icon is `.icon[data-icon=github|linkedin|telegram]{mask-image:url("data:image/svg+xml,…")}` over a shared `.icon{background:currentColor;mask-position:50%;mask-size:contain;mask-repeat:no-repeat}`. Color therefore comes only from `currentColor`, which is `--color-contact-ink` inherited from the card (so it inverts with the theme) and becomes `--color-contact-accent` on `.pill:hover` — the same element, one property, both states.
- I decoded the three data URIs out of the built CSS and diffed each `d` against a freshly fetched upstream file: `path identical to upstream = True` for all three, and `'fill' in data uri = False` for all three (the SVGs carry no `fill`, no `color`, no `currentColor` — the default opaque black is only ever read as mask alpha). The only `fill` left anywhere in the bundle is Tailwind's `transition-property` list.
- Other build checks: `.card{background:var(--color-contact-card);color:var(--color-contact-ink)}` with both tokens emitted as `light-dark()` pairs that are the theme's own colors swapped (inverted in light and dark alike); all three social anchors carry `target="_blank" rel="noopener"` and the email is a bare `mailto:`; every `animation:` in the bundle — `spin 7s` and `gridflow 6s` included — sits inside `@media (prefers-reduced-motion:no-preference)`; `[data-reveal]` hides only under `.has-js`, so the card is complete without JS; `grep` over `src/` still finds exactly one `addEventListener('scroll'` call site (`src/lib/motion/scroll.ts`).

## Decisions the spec did not cover

1. **One new token, `--color-contact-accent: light-dark(#3ee7ff, #0a8faf)`.** Not for the card/ink inversion (I used the existing pair for that) but for the accent inside the card: `#3ee7ff` on the light card is ~1.35:1 and disappears, so the label, the email and the pill hover need `--color-accent` with its branches swapped. I first scoped it as `.contact-card { --color-accent: … }` to avoid a new name — that broke `tests/tokens.test.ts`, which maps every `--name:` in `app.css` by name and would then see two declarations of `--color-accent`. Since that test isn't mine to edit, the swapped value got its own name next to the other two. The beam and halo stay on the page's own `--color-accent`/`--color-violet`, as in the mock.
2. **Icon sources.** GitHub and Telegram are Simple Icons verbatim; LinkedIn is `mdi/linkedin` (Simple Icons dropped the LinkedIn mark) — the same source the mock itself pointed at. Inlined as paths, so no dependency and no runtime request; the mock's CDN URLs would have been a third-party fetch.
3. **No brand string is copy.** `content.json` has no `GITHUB`/`LINKEDIN`/`TELEGRAM`, so the pills iterate the `links` keys and upper-case them for the label. Adding a key to `links` grows the row; only the icon has to be drawn.
4. **Borders and the grid mask use `currentColor`/`color-mix`, not tokens** (`color-mix(in srgb, currentColor 20%, transparent)` for pill borders, `currentColor` as the opaque end of the radial mask, where only alpha matters). They invert with the card for free.
5. **Two sizes stayed local instead of becoming tokens**, both used once: the email's `clamp(22px, 2.9vw, 34px)` (the mock's `cqw` converted the way the existing tokens were) and the card padding, whose floor I lowered from the mock's 36px to 28px so a 320px screen keeps some line length inside `container-page`'s own 20px.
6. **No `&lt;script&gt;` in the component.** `Base.astro` already calls `bindReveals()` over the whole document, so the section only ships `data-reveal`; a second call would double-observe.
7. **Not done, deliberately:** no custom focus ring. `DESIGN_SPEC` §4 asks for one on everything interactive and notes it is absent from the mock — nothing in the repo implements it yet, so it belongs to a site-wide pass rather than to this card, and the default UA outline is untouched in the meantime.
8. **Worth knowing:** lightningcss emitted the icon masks unprefixed (it only prefixed the pre-existing `.hero-net` gradient mask), so the icons need Safari 15.4+ / any current browser. I left the output as the toolchain produced it rather than hand-writing `-webkit-` copies.</result>
