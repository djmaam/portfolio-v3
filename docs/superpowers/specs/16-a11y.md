# 16 · Accessibility pass — spec

Issue: [PV3-21](https://linear.app/portfolio-djmaam-v3/issue/PV3-21) · Branch: `feat/16-a11y`
Design: `handoff/DESIGN_SPEC.md` §4, §6 · `handoff/README.md` rule 5

## Goal

The first block that reads the whole site at once. Every section was built in isolation,
so this is where cross-component inconsistencies surface.

## Context

Every section is merged. The site has ten components, two routes, two themes, and a
`reduce` mode.

**The focus ring is missing.** `DESIGN_SPEC` §4 asks for a `2px accent` ring with a 2px
offset on everything interactive, and notes it is absent from the mock. Three separate
agents flagged it while building their sections and correctly left it alone as
cross-cutting work. Today `src/components/Projects.astro` has the site's only
`:focus-visible` rule.

## Scope

### 1. Global focus ring

One rule in `app.css`:

```css
:focus-visible {
  outline: 2px solid var(--color-accent);
  outline-offset: 2px;
}
```

`:focus-visible`, not `:focus` — a mouse click on a button must not leave a ring behind.

**The inverted contact card is the exception that proves the rule.** `--color-accent`
inside it resolves against an inverted background, exactly the contrast bug issue 13
found. Inside the card the ring uses `--color-contact-accent`.

Remove the local rule from `Projects.astro` once the global one covers it — a duplicate
that drifts is worse than none.

### 2. Contrast, as a permanent test

Do not eyeball this and do not check it once by hand. `src/styles/app.css` holds every
color as a `light-dark(a, b)` pair, so the ratios can be computed:

`tests/contrast.test.ts` parses the tokens out of `app.css`, computes the WCAG 2.1
relative-luminance ratio for each pair below, and asserts the threshold **in both
themes**:

| foreground | background | minimum |
|---|---|---|
| `ink` | `bg` | 4.5 |
| `dim` | `bg` | 4.5 |
| `dim` | `surface` over `bg` | 4.5 |
| `accent` | `bg` | 3.0 (large/medium text only — see below) |
| `contact-ink` | `contact-card` | 4.5 |
| `contact-accent` | `contact-card` | 4.5 |

`DESIGN_SPEC` §6 allows accent as text only at ≥15px or weight 500, which is the
large-text threshold of 3:1. The test encodes that, and a second assertion greps the
components: any rule setting `color: var(--color-accent)` must also set a
`font-size` ≥ 15px or a `font-weight` ≥ 500 in the same block. If a component violates
it, fix the component, not the test.

This is a test rather than an audit because tokens will change again.

### 3. ARIA and semantics audit

Verify across all ten components, and fix what is wrong:

- Toggles carry `aria-label` and, where they express a binary state, `aria-pressed`.
- Decorative glyphs (✳, the ASCIImoji, the console dots, the step dots) are `aria-hidden`.
- The canvas is `aria-hidden` and `pointer-events: none`.
- Preview iframes are `aria-hidden` and `tabindex="-1"` — never a tab stop.
- The duplicated marquee halves are `aria-hidden`, so each technology is read once.
- The console log is `role="log"` with `aria-live="off"` (issue 06 §7 explains why, and
  that decision stands).
- One `<h1>` per page. Section headings descend without skipping a level.
- Every `<section>` with an id has an accessible name.

### 4. Keyboard traversal

Tab through both routes and confirm: order follows the visual order, focus is always
visible, nothing traps it, and every interactive element is reachable. The nav is sticky,
so also confirm a focused element never lands underneath it — `scroll-margin-top` was
added in issue 08 for fragment jumps; focus scrolling may need `scroll-padding-top` on
the scroll container, which is a different property.

Add a skip link to `<main>` as the first focusable element. It is the one addition here
that is not in the design: with a sticky nav and eight sections, tabbing past the nav on
every page load is exactly what skip links exist for. Visible only on focus.

### 5. Reduced motion, whole-site sweep

With `reduce`: no canvas in the DOM, no marquee, no sticky pinning, no shimmer, no
scramble, no typing, no ASCIImoji rotation, no console cycling, no aurora animation, and
every `[data-reveal]` and `[data-boot]` at full opacity.

Each of those already has a test in its own block. Add one integration test that greps
the built CSS and asserts **every** `animation:` and `transition:` that moves something
sits inside `@media (prefers-reduced-motion: no-preference)`. That is the assertion no
single block could make.

### 6. No JavaScript

Both routes fully readable and navigable. The language toggle works. This too gets an
integration test over the built HTML rather than a manual pass.

## Acceptance criteria

- [ ] `bun test`: every contrast pair in the table meets its threshold in both themes.
- [ ] `bun test`: no component sets `color: var(--color-accent)` on text below 15px and lighter than weight 500.
- [ ] `bun test`: every `animation:` in the built CSS is inside a `no-preference` block.
- [ ] `bun test`: exactly one `<h1>` per built page; no heading level is skipped.
- [ ] `bun test`: every `<iframe>` in the built HTML has `aria-hidden` and `tabindex="-1"`.
- [ ] `bun test`: the skip link is the first focusable element in both pages.
- [ ] The global focus ring covers every interactive element; `Projects.astro`'s local rule is gone.
- [ ] Inside the contact card the ring uses `--color-contact-accent`.
- [ ] A keyboard pass over both routes: order matches visual order, focus always visible, no traps, nothing hidden under the sticky nav.
- [ ] `bun run lint`, `bun test` and `bun run build` pass.

## Out of scope

Playwright and Lighthouse (issue 17). Company logos (issue 15). Any redesign — this block
fixes accessibility defects, it does not restyle sections.
